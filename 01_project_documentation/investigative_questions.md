# Investigative Questions
## Banking Transaction Intelligence & Performance Analysis

These questions guide the investigation of the BankSim transaction dataset. They connect the business objectives to the analysis we will perform using SQL Server, Python and Power BI.

### IQ01 — Overall Transaction Activity
What is the overall volume and value of transactions recorded in the dataset?

- How many transaction records are available?
- What is the total transaction value?
- What are the average, minimum and maximum transaction amounts?

### IQ02 — Customer Transaction Behaviour
Which customers account for the highest transaction volumes and values?

- Which customers transact most frequently?
- Which customers have the highest cumulative transaction values?
- How do transaction frequency and average transaction amounts vary across customers?

### IQ03 — Customer Transaction Concentration
How concentrated is transaction activity among customers?

- What proportion of transaction activity is generated by the most active customers?
- Is transaction value distributed evenly or concentrated among a smaller group?
- Which customers contribute disproportionately to overall activity?

### IQ04 — Merchant Category Performance
Which merchant categories account for the largest transaction volumes and values?

- Which categories record the highest transaction frequency?
- Which categories have the highest total and average transaction amounts?
- How do customer spending patterns differ across merchant categories?

### IQ05 — Geographic Transaction Patterns
Can transaction activity be meaningfully compared across customer and merchant locations?

- Are there identifiable differences between customer and merchant locations?
- Can transaction activity be grouped meaningfully by geographical area?

**Data limitation:** The dataset's `zipcodeOri` and `zipMerchant` fields each contain only one unique postcode. Consequently, meaningful geographical comparisons cannot currently be performed. This question is retained for documentation but excluded from the measurable analysis.

### IQ06 — Unusual Transaction Behaviour
Are there transactions or customer behaviours that deviate significantly from typical patterns?

- Are there unusually high or low transaction amounts?
- Are there customers with unusually high transaction frequencies?
- Are there unusual patterns across merchant categories?
- Do any patterns warrant further investigation?

An unusual transaction is not automatically fraudulent. Anomaly indicators must be distinguished from confirmed fraud.

### IQ07 — Temporal Transaction Patterns
How does transaction activity change over the available time steps?

- Which time steps record the highest and lowest transaction volumes?
- How does transaction value change over time?
- Are there identifiable peaks, fluctuations or recurring patterns?

The meaning of the dataset's `step` field must be verified before interpreting it as a calendar period.

### IQ08 — Data Quality and Reliability
Does the dataset contain quality issues that could affect the accuracy of the analysis?

- Are there missing values?
- Are there duplicate records?
- Are there invalid or inconsistent values?
- Are categorical fields consistently formatted?
- Are numerical fields within reasonable ranges?

### IQ09 — Potential Customer Engagement Opportunities
What customer and spending patterns could inform potential customer engagement strategies?

- Which customer groups demonstrate high transaction activity?
- Which merchant categories attract the greatest spending activity?
- Are there identifiable patterns that could inform targeted engagement or merchant partnerships?

Recommendations must remain within the limits of the available dataset.

### IQ10 — Fraud Labels and Anomaly Concentration
How are the dataset's fraud labels and unusual transaction patterns distributed across customers, merchants and time?

- What proportion of transaction records carry a fraud label?
- Are fraud-labelled records concentrated among particular customers?
- Are certain merchant categories associated with higher proportions of fraud-labelled records?
- Do fraud-labelled records show unusual transaction amounts or temporal patterns?

**Data limitation:** The dataset does not provide meaningful geographical variation, so the geographical component of this investigation cannot be assessed. Fraud labels are synthetic dataset labels and should not be presented as independently verified real-world fraud.

---

## Investigation Principles

The analysis will follow these principles:

1. Findings must be supported by evidence from the dataset.
2. Unusual behaviour must not automatically be classified as fraud.
3. Data limitations must be disclosed rather than concealed.
4. Transaction records must not automatically be assumed to represent successfully completed transactions.
5. Business recommendations must be proportionate to the evidence available.
